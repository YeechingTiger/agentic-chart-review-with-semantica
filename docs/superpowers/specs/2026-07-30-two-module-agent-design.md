# 两个模块：跑病历的，和评测的

**日期**：2026-07-30
**状态**：设计已定，待实施

这份文档正文用大白话写。代码里的名字**一个都不改**（`spec`、`trace`、`gate` 这些照旧），
因为 `spec_hash`、`SPEC_INSUFFICIENT`、`gate_validated` 这几个字段已经写进了所有历史存档，
改了以后过去的 run 和以后的 run 对不上账。文档末尾有对照表。

---

## 1. 一句话

**一边跑病历出答案，一边看这些答案跑得对不对。评测这边分两种做法——死板的程序算，和 AI 看
工作记录找原因——两种都产出同一种东西：信号。**

---

## 2. 模块一：跑病历（run）

### 它干什么

打开一个病人的全部病历，按规定找出要填的几项（长在哪、什么类型、良性恶性），每一项都要
指出是在哪份报告的哪句话里看到的。指不出来就不许交答案。

**这块基本已经做完了**，`acr run` / `acr batch` / `acr extract` 都能跑。这一期只补一个洞。

### 它上岗带三样东西

**一、填表规定**（代码里叫 spec）
写死的、医生签过字的、锁死的。规定这次填哪几项、什么值算对、什么记录够格当依据。
**机器人只能照办，不能改，也不能不听。**

**二、经验卡**（代码里叫 skill，这个词保留，因为是目录名 `skills/*/SKILL.md`）
不是规定，是"老手怎么干这活"。机器人可以不照做，但要在工作记录里写清为什么。

分三个槽，一个槽装一类：

| 槽 | 装什么 | 带几张 | 现有的卡 |
|---|---|---|---|
| `task` | 这个活怎么干 | 0–1 张 | `store-icdo-coding`、`store-staging` |
| `search` | 病历怎么翻 | **恰好 1 张**（可以是"什么都不给"） | 待建 |
| `general` | 任何病历都用得上的功夫 | 若干张 | `chart-triage`、`thread-chasing`、`coverage-judgement` |

**为什么"病历怎么翻"要单独占一个槽、一次只装一张：**
这样才能做干净的对照试验。同样的病人、同样的规定、同样的其他卡，**只换这一张**再跑一遍，
两次结果的差别就纯粹是这张卡带来的。混在一起就永远不知道是哪个变化起的作用。

`docs/SEARCH_PLANNING_PILOT.md` 已经证明这种对照是刚需：以为有用的检索经验，实测下来
准确率反而低一点（4/10 对 3/10）。没有干净对照，这个结论根本得不出来。

**三、工作记录**（代码里叫 trace）
每一步都记：搜了什么词、翻了哪几份报告、为什么下这个结论、花了多少钱。

### 要补的洞

技能槽的机器**已经在了但是空的**：`runtime_profiles.py` 里的 `_PROFILE_SKILLS` 是个空字典，
所有 profile 都退回同一张 `coverage-judgement`。所以现在**换 profile 并不会换经验卡**，
对照试验换的只是别的东西。

补三件事：

1. 每张卡的开头声明自己属于哪个槽（`slot: task | search | general`）。装错槽直接报错，
   不许静默通过。
2. `_PROFILE_SKILLS` 按槽填上，加载时校验：`search` 槽多于一张 → 报错。
3. 命令行加 `--skills` 参数，不用新建 profile 就能临时换一张卡，方便做对照。
4. 存档单里按槽分别记每张卡的内容指纹——两次 run 换了哪个槽，一眼看得出。

### 新建的"病历怎么翻"卡

先落两张，对应已经跑过的两个试验臂：

- `search-native`：自己看着办，觉得查够了就停
- `search-preplanned`：先按以前统计的经验排个顺序再查

以后加策略就是加一个目录，不改代码。

## 3. 模块二：评测（eval）

### 它干什么

它不看病人、不填表。它看的是**跑病历那边留下的工作记录**，外加一样跑病历那边绝对看不到的
东西：**标准答案**。它回答"这次为什么对了，那次为什么错了"。

### 两种做法，一个出口

这是这一期最要紧的结构。评测分两种，做法完全不同，但**产出同一种东西**：

```
        工作记录 + 标准答案
                │
        ┌───────┴───────┐
        │               │
   程序算的         AI 看的
   （死板）         （灵活）
        │               │
        └───────┬───────┘
                ▼
             信号
```

"信号"这个东西代码里已经有了（`kernel.py` 的 `SignalEnvelope`），有七种类型，
带证据指针和严重程度。两边都往这个格式里写，下游就只认一种东西。

#### 做法一：程序算的（不用 AI）

一是一二是二，跑一百遍结果一样。**已经有了**（`evals.py`、`audit_loop.py`）：

- 答案和标准答案**一样吗**——就是 `==`，不是"相似度"
- 引用的原文**真的在那份报告的那个位置吗**——回原文核对
- 有没有报告翻到一半就断了
- 花了多少钱、调了多少次模型
- 有没有已知的异常行为（比如反复搜同一个词卡死）

#### 做法二：AI 看的

程序只能告诉你**"错了"**，告诉不了你**"为什么错"**。找原因要通读工作记录、要对比、
要归纳——这是 AI 的活。**每一种复盘思路 = 一张经验卡**（`slot: eval`）。

先落四张：

| 卡 | 干什么 |
|---|---|
| `eval-contrast-traces` | 把答对的和答错的工作记录摆一块，看搜索词和顺序差在哪 |
| `eval-cluster-failures` | 十个病人错了六个，是同一个毛病还是六个毛病 |
| `eval-missed-evidence` | 答案其实躺在某份报告里，为什么没翻到那份 |
| `eval-overconfidence` | 答得斩钉截铁但答错了，当时凭的什么 |

**加复盘角度 = 加一张卡，不改代码。** 这是这个模块的扩展方式。

### 一条不能破的规矩：判分不许交给 AI

**"答得对不对"只能用程序算，AI 没有这个权力。**

为什么这条要写死在代码里而不是靠自觉：AI 判分会出一种特别阴的错——

> 病历里确实没写，机器人老老实实答"证据不足"。**这是对的行为。**
> 但 AI 判分器会觉得"你没完成任务"，扣分。
> 长期拿这种分数调教机器人，等于教它**碰到不确定就编一个**。
> 而不确定的病例，恰恰是最不能编的。

所以怎么落地：

- 评测 AI 的工具箱里**根本没有**一个"我宣布这题答错了"的按钮。它想知道对错，
  只能调用程序去问。
- 每张评测卡开头声明自己**允许判断哪几类问题**（`judges:`）。声明之外的判断，
  lint 能查出来。
- 现有的 `judge.py` 围栏（有确定性检查的地方禁止用 AI judge）继续有效，一个字不改。

### 单个和批量都要能跑

现在的现状是**能跑但入口是散的**：`acr eval` 一套、`acr audit` 一套、`acr evaluation`
一套、`acr attribute` 一套（这个已经有 case 和 batch 了）。

这一期做一个统一入口，把两种做法都收进来，单个和批量都有：

```
acr signal run    --kind rule  ...    单个，程序算
acr signal run    --kind agent ...    单个，AI 看
acr signal batch  --kind rule  ...    批量，程序算
acr signal batch  --kind agent ...    批量，AI 看
```

**为什么叫 `acr signal` 而不是塞进现有的 `acr eval`：** `cli_eval.py` 开篇就承诺
"这个组里没有一条命令会调模型"，`evals.py` 还有测试走 import 关系图钉着这句话。
AI 复盘要调模型，加进去就把那句承诺变成了一句留在纸上的空话。所以新开一个组，
名字用你自己的说法——两种做法都产出信号，这就是问信号的地方。

旧命令**全部保留不动**（`acr eval`、`acr audit`、`acr attribute`），新入口是薄薄一层壳，
底下调的是同一批已经测过的代码。

---

## 4. 两个模块必须隔开

评测那边看得到标准答案，跑病历那边**绝对不能看到**——不然测出来的准确率是假的。

两边不在同一个进程里跑，现在就有测试卡着这条线（`tests/test_evals.py` 走 import 关系图，
发现跑病历那边能摸到标准答案就失败）。继续留着，不动。

---

## 5. 这一期**不做**的

**两个模块的联动。** 评测发现的问题自动变成新经验卡、自动改填表规定、自动更新经验库——
全部推迟。

理由：先把两个各自做扎实，看到真实产出再设计联动。现在设计等于凭空猜测评测会产出什么。
